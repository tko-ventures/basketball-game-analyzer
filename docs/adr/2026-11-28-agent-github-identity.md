# Dedicated GitHub App bot identity and per-agent provenance trailers for AI agents

- **Date:** 2026-11-28
- **Status:** Accepted
- **Area:** Infra / Process
- **Decider:** Tomasz

## Context

All AI coding agent contributions to `tko-ventures/basketball-game-analyzer` currently attribute to `tk-o` (`Tomasz Kopacki <tomasz@kopacki.net>`) across four channels: `~/.gitconfig` (`git commit`), the `tk-o` SSH remote (`git push`), the local `gh` CLI keyring, and T3 Code's built-in GitHub MCP write tools (`pull_request_*`, `create_issue`, `comment_on_issue`). Beyond hiding human vs. agent authorship, this blocks formal review governance: GitHub forbids self-approval, so `tk-o`-opened agent PRs cannot receive `@tk-o` approvals or enforce `.github/CODEOWNERS` on `main` (`#62`). Tracked under Epic `#68`.

## Decision

1. **Private Organization GitHub App (`tko-ventures`, e.g. `tko-agent` → `tko-agent[bot]`):** Install a private org App on this repository, minting short-lived 1-hour installation tokens from `~/.config/bga/github-app.pem` and `~/.config/bga/github-app.env` (never committed) via zero-dependency stdlib + `openssl` helpers (`scripts/agent_identity.py`). Grant `Contents: R/W`, `Pull requests: R/W`, `Issues: R/W`, `Workflows: R/W` (gated by `.github/CODEOWNERS` + `main` branch protection), `Checks: R`, `Actions: R` (or `R/W` for reruns), `Metadata: R`, and **`Administration: No access`**.
2. **Single shared bot identity + per-agent provenance trailers and footers:** All AI agents (Claude, Antigravity, Grok, Codex) commit and push as `<bot_user_id>+<slug>[bot]@users.noreply.github.com` while appending `Agent: <harness>/<model>` trailers (preserving `Co-authored-by:`) and compact `<sub>Agent: ...</sub>` comment footers so individual agents/models stay distinguishable without managing multiple Apps. Uncommitted human edits in `data/labels/` committed by an agent per `AGENTS.md` use an explicit `--as-human` mode (`Author: Tomasz Kopacki`, `Committer: <slug>[bot]`).
3. **Mechanical guardrails & T3 Code MCP routing:** Add a local `pre-commit` guard (`scripts/check_agent_identity.py`) that blocks agent shells (detected via harness env vars) from committing as `tomasz@kopacki.net` unless explicitly flagged for human label edits, while staying silent in Tomasz's plain terminal and CI. Route git writes (`scripts/agent_git.py`) and GitHub writes (`scripts/agent_gh.py`) through the App token in `AGENTS.md` while keeping T3 Code read/link/watch tools (`link_pull_request`, `watch_pull_request`, `link_issue`, `pull_request_read`, `ci_logs`). Extend `scripts/check_pr_oversight.py` to summarize PR commit authorship.
4. **Risk-tiered `main` merge policy via `CODEOWNERS` + `0` base approvals:** Configure `main` branch protection / ruleset with **Require a pull request before merging** (blocking direct `git push` to `main` by the App), `required_approving_review_count: 0`, `require_code_owner_reviews: true`, `dismiss_stale_reviews: true` (preventing post-approval edits from slipping past review), `required_conversation_resolution: true` (blocking merge on unresolved review threads such as Greptile findings), required status checks (`pytest`, `pre-commit hooks`, `gitleaks`, `osv-scanner (PR delta)`, `dependency-review`, `pr-oversight`, `CodeQL`), the **App excluded from all bypass lists**, and no global push restriction blocking PR merges on unowned files. Expand `.github/CODEOWNERS` (`@tk-o`) to cover all human-decision, governance, supply-chain, config, and data surfaces: security & governance (`/.github/`, `/.pre-commit-config.yaml`, `/.gitleaks.toml`, `/AGENTS.md`, `/tests/test_security_policy.py`, `/scripts/check_pr_oversight.py`, `/scripts/run_gitleaks.py`, `/scripts/security_digest.py`, `/scripts/agent_*.py`, `/scripts/check_agent_identity.py`), decisions & architecture (`/docs/adr/`, `/docs/architecture.md`, `/docs/architecture-c4-view.md`), dependencies & remote compute (`/pyproject.toml`, `/uv.lock`, `/src/bga/remote/`, `/src/bga/train/dispatch.py`), and pipeline configs & data/labels (`/configs/`, `/data/`). Extend `pr-oversight` so any PR adding an inline security suppression (`# noqa: S*`, `gitleaks:allow`, `nosec`, `shellcheck disable`, `zizmor:ignore`) cannot auto-merge on an unowned path without `@tk-o` approval.
5. **Rejected alternatives:** A dedicated machine user (e.g. reusing `tko-ventures-grokbot`, currently `admin` on this repo and scheduled for audit/downgrade in `#70`) lacks the official `[bot]` badge, relies on long-lived PATs, and fits awkwardly with GitHub's single-free-account ToS (kept only as fallback if signed feature-branch commits are ever mandated). Trailers or comment prefixes alone keep GitHub UI authorship as `tk-o` and cannot unlock `@tk-o` PR approvals. Blanket human-only merges slow routine bug fixes, while `1`-approval auto-merge still blocks trivial fixes on human taps; path-based `CODEOWNERS` lets Tomasz tighten or loosen coverage at any time.

## Consequences

- Unlocks formal `@tk-o` PR approvals and hard `CODEOWNERS` review gates on `main` for ADRs, governance/CI, dependencies, remote compute, `/configs/`, and `/data/` (with stale approvals dismissed on new pushes), while allowing routine bug-fix and test PRs touching only unowned paths to squash-merge autonomously once all required CI/security checks pass and conversations are resolved.
- Accepting this ADR partially supersedes the blanket *"never merge a pull request without Tomasz"* clause of [`docs/adr/2026-11-18-python-style-and-quality-standards.md`](2026-11-18-python-style-and-quality-standards.md) and `AGENTS.md` (updated in `docs/adr/README.md` and `AGENTS.md` in `#73`).
- Squash-merged agent PRs retain `<slug>[bot]` as the commit Author on `main` with GitHub's `Verified` signature; local feature-branch commits pushed via Git CLI show `Unverified` (GitHub does not attach SSH/GPG keys to `[bot]` accounts), which is acceptable while signed branch commits are not required.
- Rollout is tracked across Epic `#68` and sub-issues `#69` (ADR), `#70` (human-only App setup), `#71` (wrappers & tests), `#72` (guardrails, expanded `CODEOWNERS`, and `pr-oversight` inline-suppression gate), and `#73` (`AGENTS.md`, two-tier `main` protection, and E2E verification proving unowned PRs merge when green while the App token is rejected (`403`) on unapproved `CODEOWNERS` PRs, stale-approval dismissals, and unapproved inline security suppressions).
